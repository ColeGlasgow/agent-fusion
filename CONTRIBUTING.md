# Contributing to agent-fusion

Thanks for your interest. agent-fusion is in the design phase, so the most valuable contributions right now are issues, design proposals, and feedback on the planned architecture.

## Ways to contribute

- **Open an issue** for bugs, design questions, or feature ideas. Use the templates in `.github/ISSUE_TEMPLATE/` so the right context is captured.
- **Propose a design change** by opening an issue tagged `design` before submitting a PR. This avoids wasted work on direction the project isn't taking.
- **Submit a pull request** for a scoped change once the direction is agreed.

## Pull request process

1. Fork the repo and create a branch from `main`. Use a descriptive branch name, e.g. `feat/router-rules` or `docs/clarify-memory`.
2. Keep changes focused. One logical change per PR.
3. Match the existing style. Run formatters and linters before pushing once they are configured.
4. Write a clear PR description: what changed, why, and how it was tested. The PR template will prompt for these.
5. Link any related issue with `Closes #<number>` when applicable.
6. A maintainer will review. Address feedback by pushing additional commits rather than force-pushing, unless asked.

## Commit messages

Use present-tense, imperative subject lines under 72 characters (e.g. `add base agent interface`). Include a body when the *why* isn't obvious from the diff.

## Code of conduct

By participating, you agree to abide by the [Code of Conduct](CODE_OF_CONDUCT.md).

## Security

Do not open public issues for security vulnerabilities. Follow the process in [SECURITY.md](SECURITY.md).
